---
title: TikTok
description: Prepare TikTok creator choices and publish verified media URLs with explicit consent, privacy settings, and processing checks.
icon: tiktok
---

The direct TikTok adapter accepts an existing access token and creator `openId`. The server package also provides `tiktokOAuth` for TikTok Login Kit authorization, PKCE, and creator discovery. Use `ConnectionManager` to bind the callback to the authenticated tenant, show the discovered creator, and persist credentials through an encrypted `credentialSink`. Its default scopes are `user.info.basic` and `video.publish`, sent comma-delimited; refresh with `refreshOAuthToken("tiktok", ...)` and persist any rotated refresh token. OAuth consent does not replace the adapter’s creator preview and publish consent requirements.

```ts
import { createSocial, connectedAccountRef } from "@opencoredev/social-sdk";
import { tiktok } from "@opencoredev/social-sdk/tiktok";

const social = createSocial({
  backend: tiktok({
    auth: { accessToken: process.env.TIKTOK_ACCESS_TOKEN!, openId: process.env.TIKTOK_OPEN_ID! },
    verifiedMediaOrigins: ["https://media.example.com"],
  }),
});
const account = connectedAccountRef({
  backend: "default",
  platform: "tiktok",
  accountId: process.env.TIKTOK_OPEN_ID!,
});
const creatorInfo = await social
  .native("default", { acknowledgeUnsafe: true })
  .creatorInfo(account, {
    correlationId: "creator-preview",
    retryBudget: { maxAttempts: 1, maxElapsedMs: 10_000 },
    authorization: { tenantId: "tenant", principalId: "user" },
  });
// Render creatorInfo.privacyLevels and let the creator choose one of the returned values.
const privacy = "PUBLIC_TO_EVERYONE";
const result = await social.posts.publish({
  targets: [
    {
      account,
      options: {
        consentGiven: true,
        creatorInfo,
        privacy,
        disableComments: false,
        disableDuet: false,
        disableStitch: false,
        brandedContent: false,
        ownBrand: false,
        photoCoverIndex: 0,
      },
    },
  ],
  content: {
    text: "A creator-approved caption",
    media: [
      {
        kind: "video",
        source: { kind: "https-url", url: "https://media.example.com/video.mp4" },
        durationSeconds: 8,
      },
    ],
  },
});
```

The adapter uses verified `PULL_FROM_URL` media origins. It supports one video or 1–35 photos, explicit privacy and interaction choices, captions up to the format limit, and creator information bound to the same backend/account. It rejects missing consent, stale creator choices, unverified origins, unsupported schedules/replies/links, and unknown media duration where required.

The initial publish call returns `accepted` with a `publish_id`. Reconcile through `posts.getDelivery`: processing states remain `processing`, a confirmed failure remains `failed`, and a public ID is required before reporting `published`. Draft/inbox and public posting have different upstream review and audit requirements; the SDK does not claim approval or silently change privacy.

TikTok's [content sharing guidelines](https://developers.tiktok.com/doc/content-sharing-guidelines/) describe creator preview, consent, privacy and app-audit requirements. Keep tokens server-side and treat media URLs, creator data and publish IDs as sensitive. Repository evidence is offline contract and mocked transport coverage; no TikTok app or creator account has been live-verified.
