---
title: Direct integrations
description: Call supported platform APIs without a managed social provider while keeping authorization in your application.
---

Direct mode uses the developer's own platform application and credentials. It does not require Zernio, Post for Me, a Social SDK account, or a hosted Social SDK service.

Each direct integration documents its actual authorization model. An OAuth platform is not presented as a generic API-key adapter. Account eligibility, review status, required scopes, token refresh behavior, upload processing, quotas, and upstream charges remain platform-specific.

Direct integrations still use the common account, content, media, outcome, error, and request-context contracts. Typed native access preserves features that do not fit the shared operation model, but application-level tenant authorization remains required around that escape hatch.

Before enabling a direct route in production, require implementation and contract-test evidence for the operation, then complete the platform's credential, account, review, and live-verification steps. Missing credentials are a live-evidence blocker; they are not evidence that an adapter works.
