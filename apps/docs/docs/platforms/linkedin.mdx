---
title: LinkedIn
description: Publish as an explicit LinkedIn author while preserving native URNs, permissions, image processing states, comments, and metrics.
---

The direct LinkedIn adapter supports text and one registered image, native post reads, comment reads/replies, and returned social-action counts. Configure a member or organization author URN and an explicit monthly API version. Existing authorization is server-owned; this adapter does not grant organization roles or perform account selection for you.

```ts
import { createSocial, connectedAccountRef } from "@opencoredev/social-sdk";
import { linkedin } from "@opencoredev/social-sdk/linkedin";

const social = createSocial({
  backend: linkedin({
    auth: {
      accessToken: process.env.LINKEDIN_ACCESS_TOKEN!,
      author: "urn:li:organization:123",
    },
    apiVersion: "202609",
  }),
});
const account = connectedAccountRef({
  backend: "default",
  platform: "linkedin",
  accountId: "urn:li:organization:123",
});
const prepared = social.posts.prepare({
  targets: [{ account }],
  content: { text: "A short update" },
});
```

Preparing performs no network requests. Publish only after your application has authorized the selected account and obtained the intended content. This slice uses public visibility. Private visibility, multi-image posts, video and structured article cards fail local preparation instead of being silently changed.

Upload an image through `social.media.upload`, store its account-bound media reference, and use that reference in a publish request. The adapter checks the upstream owner and requires `AVAILABLE` before creating the post. A still-processing image needs an explicit later check through the native image-status helper. It does not start polling in the background.

Post creation returns its native URN in the `x-restli-id` header. Missing native identity produces an unknown outcome. Preserve the result and reconcile before retrying. Replies require the complete `commentUrn` returned by comment reads, including its activity and comment identifiers.

Member publishing needs `w_member_social`; organization publishing needs `w_organization_social` and an eligible page role. Member read access is restricted. Community Management comments and social actions use separate feed permissions. A token that publishes successfully may still lack read permission. Check the current LinkedIn product approvals and role rules before enabling these operations.

Organization account metrics read the total follower count from the versioned `networkSizes` endpoint. They require `rw_organization_admin` and an administrator role for the configured organization. Member-profile account metrics are unavailable in this slice.

Metrics contain only counts returned by LinkedIn. Missing counts remain absent, and request time is recorded as `fetchedAt`, not `measuredAt`. Messaging is unsupported. Current evidence is offline contract tests; no account, app approval or live post has been verified.

Sources: [Organization follower count](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-lookup-api#retrieve-organization-follower-count), [Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api), [Images API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/images-api), [Comments API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/comments-api).
